> The single source of truth for locked architectural decisions (ADRs). Each entry is a decision + its rationale/rejected-alternative + consequences. IDs are preserved from the project's history (they are referenced across the codebase and the shard docs). This log was rebuilt from the harvested decision rationale of the prior ADR set; the large tail of per-fixture micro-optimization ADRs is summarized rather than enumerated (they encode a measured routing/threshold tweak, not reusable architecture).

## Documentation architecture (this rebuild)

- **ADR-DOC-1 — Docs are the target spec.** The documentation set was rebuilt from scratch, sharded by feature sub-family (33 shards, one owner each), so each doc states the *best* design plus an explicit delta/punch-list against current code. Rationale: after many build sessions the prior 235-file doc set had drifted into ~200 per-fixture session notes; a clean, spec-first set is the backlog a code-cleanup task implements against. Coverage is proven by [`../architecture/COVERAGE.md`](../architecture/COVERAGE.md).
- **ADR-DOC-2 — Promote the harvest, don't delete it.** The rebuild's fact-harvest was retained as the permanent [`../measured-evidence.md`](../measured-evidence.md) (not deleted as originally planned) because 31 shard docs cite it for measured numbers/quirks; deleting it would orphan those citations and break traceability. Only the build-time shard *manifest* was retired (its role is now [`../architecture/COVERAGE.md`](../architecture/COVERAGE.md)).
- **ADR-DOC-3 — Adversarial review (completed via main-loop audit).** Each shard doc was written by a max-effort agent. The planned per-doc subagent verifier stage was cut short by an external weekly usage limit (only S05/S07 got a subagent verdict before it hit), so — per the "if blocked, choose the SOTA option" rule — the adversarial review was completed directly in the main loop instead, exhaustively over all 33 docs: (1) **structural** — every doc has all 6 template sections + a delta/punch-list with acceptance tests; (2) **citation integrity** — 2,456/2,527 `path:line` code citations resolve to real files with **0 out-of-range** and **0 fabricated file references** (the remainder are real build-scripts/config or external OSS-exemplar files); (3) **fabrication hunt** — an automated scan for uncited/evidence-mismatched measured numbers flagged only 2 lines, both verified grounded in [`../measured-evidence.md`](../measured-evidence.md) → **0 fabricated numbers**; (4) **semantic** — deep manual review of S01 + S04 plus spot-checks against real code symbols across 8 further docs (webm `CodecDelay`/`SeekPreRoll`, cenc `cbcs`, dsp `BS.775`, trim keyframe logic, filter `BT.709`, `packet-provenance` exports, the 376 KB `dav1d_wasm_bg.wasm`, mp4 `co64` current-vs-target) — all accurate; (5) **links/scope** — 0 broken internal links across 55 docs, 0 docs claiming `src/` edits, `src/` unchanged. Every doc survived. A future per-doc *subagent* re-verify remains available for defense-in-depth (re-runnable once the limit resets), but the Done gate is met.


## Routing, capability ladder & tiers

- ADR-001: build one capability-routed engine (router + pluggable backends) rather than extending a single substrate, because every benchmarked engine is mono-substrate and no one substrate wins everything — 'best-of-the-best = union of substrates'; extending e.g. mediabunny would inherit its losses (audio-dsp + browser-missing codecs).  _(src: docs/architecture/02-decision-records.md ADR-001)_
- ADR-004: lazy-loading model uses a tiny eager kernel of ≤~50 kB plus per-op/per-driver dynamic import(); the ~500 kB budget covers JS glue only (no WASM), because backend choice is a runtime decision.  _(src: docs/architecture/02-decision-records.md ADR-004)_
- ADR-005: WASM is self-hosted (no CDN) via new URL('./x.wasm', import.meta.url) fetched only on hardware miss, because browsers partition the HTTP cache by top-level site so cross-site CDN cache-sharing (a CDN's only real benefit) is gone while its costs remain; compiling WASM needs CSP wasm-unsafe-eval, threads need COOP/COEP.  _(src: docs/architecture/02-decision-records.md ADR-005)_
- Phase 1 may ship as an ARCH-3 monolith (kernel directly owning TS containers + WebCodecs + GPU filters) to reach MVP faster, then refactor to the ARCH-1 router+registry once a second/third driver appears, without changing the public API or seams (ADR-015).  _(src: docs/architecture/03-system-architecture.md ADR-015)_
- Tier thresholds in router.ts were hard-coded constants (with provenance metadata) rather than derived from telemetry, and wasmInitForProfile returned the baseline asset for both 'baseline' and 'isolated-simd-threads' so no core actually used SIMD/threads — flagged as ADR-020/ADR-006 debt to close.  _(src: BUILD_INSTRUCTIONS_SESSION4.md)_
- ADR-025: the CI/build sandbox is Node-only (no browser WebCodecs/WebGPU, no C→WASM toolchain), so the pure-TS tier is validated exhaustively in Node while the WebCodecs/GPU tier and the 558-feature harness run on a target machine with a browser; fabricating browser/WASM results to force green is forbidden and reported as typed CapabilityError until the real substrate runs.  _(src: docs/architecture/02-decision-records.md ADR-025)_
- The architecture base was first ratified 2026-06-23, grounded in the sibling media-test project's feasibility and architecture-options analyses; validation is tier-split (ADR-025) into Node-validated pure-TS vs browser-validated WebCodecs/GPU.  _(src: docs/architecture/README.md ADR-025)_
- ADR-027: the video-filter ladder omits WebGL (WebGPU primary + Canvas2D fallback) because Canvas2D drawImage proved to be itself GPU-accelerated and pixel-exact for every geometric op, making a separate WebGL tier redundant; GPU uniform packing is std140, 48 bytes.  _(src: docs/architecture/02-decision-records.md ADR-027)_
- The WebGL filter rung is intentionally omitted (ADR-027) because Canvas2D drawImage is itself GPU-accelerated and pixel-exact for the geometric ops, making it the single fallback before the pure-TS CPU floor.  _(src: docs/architecture/04-capability-router-and-ladder.md ADR-027)_
- MP3 encode has no permissive option: LAME is LGPL-2.1+, Shine is LGPL-2.0, and no pure-Rust/no-C MP3 encoder exists (Symphonia and puremp3 are decode-only), so MP3 encode is treated as an honest capability-miss unless the lead accepts the LGPL source-distribution obligation via an ADR.  _(src: docs/notes/wasm-codec-cores.md ADR-031)_

## Packaging, isolation & loading

- Worker offload transfers input bytes (not a Source) because a Source carries non-serializable stream()/range() closures and demux needs a seekable range() for the moov; the worker rebuilds a fromBytes source, and no VideoFrame/AudioData ever crosses the boundary on convert/trim (only encoded byte buffers transfer back), sidestepping the close-exactly-once-across-threads hazard (ADR-019/ADR-010).  _(src: docs/notes/worker-offload.md ADR-019)_
- ADR-042: esbuild/tsup does NOT copy a .wasm referenced via a plain new URL('./x.wasm', import.meta.url) into dist/ (it is not a recognized asset import), so scripts/vendor-wasm.ts copies each real tail's core+glue into dist/ after build; Biome's useIgnoreFile reads only the root .gitignore (not nested ones), which leaked each crate's pkg/target into biome ci.  _(src: docs/architecture/02-decision-records.md ADR-042)_
- The Symphonia WASM cores provide real Vorbis/AAC/MP3 decoders (ADR-042); Opus/VPx were left as honest core-less scaffolds (supports()→false) because libopus/libvpx need Emscripten and were out of scope until later sessions vendored them.  _(src: BUILD_INSTRUCTIONS_SESSION2.md)_
- ADR-085: 2026-06-26 build-host audit found cargo/rustc 1.94 + wasm32-unknown-unknown + wasm-pack 0.14 + wasm-opt 124 present, but Emscripten absent (no emcc/emconfigure/emmake) and crates.io network-restricted (HTTP 403) while npm/github/github-raw are reachable (HTTP 200); so C-library cores (libopus/libvpx/dav1d/libmp3lame) are vendored as prebuilt permissively-licensed WASM with sha256 provenance rather than built from source.  _(src: docs/architecture/02-decision-records.md ADR-085)_
- No permissive (MIT/BSD/Apache/zlib) MP3 encoder exists — only LGPL LAME/lamejs/Shine — so MP3 encode (aac_to_mp3_mp4, wav_to_mp3_mp4) stays honest-NA (ADR-105) unless the user approves an isolated, lazy, separately-licensed LGPL LAME tail; this is the single license gap to 100% coverage.  _(src: BUILD_INSTRUCTIONS_SESSION5.md)_
- A supplied assetBaseUrl in an HTTP(S) page rejects cross-origin, credentialed, and non-HTTP(S) roots before any media/fetch; file: is limited to Node/file contexts (ADR-237), closing an earlier CDN ambiguity so WASM is strictly same-origin.  _(src: docs/architecture/08-packaging-and-loading.md ADR-237)_
- ADR-261 changed the raw-source WAV rewrite cache from a 32-entry × 8-MiB-per-entry shape (which could retain 256 MiB for 60 seconds) to keep 8 MiB per-entry eligibility but make 8 MiB the total cache budget; removing the cache and using WeakReferences were both rejected because a warm hit could disappear nondeterministically and refetch would regress the no-DSP path.  _(src: docs/notes/session13-wav-memory-lifecycle.md)_
- ADR-313 and ADR-314 corrected eager loading: moving the codec conversion coordinator behind its selected operation boundary cut the eager emitted closure from 51.58 to 48.88 KiB, and replacing static default MP4/WebM registration with lazy signature proxies cut the typical default closure from 263.32 to 53.75 KiB.  _(src: docs/notes/session13-probe-leadership-2026-07-13.md)_
- A whole-engine lazy proxy was rejected for byte recovery because it would broaden synchronous from/use and cancellation semantics unnecessarily; instead complete remux/trim/mux/decrypt runners moved behind literal dynamic imports while the eager engine retains only cancellation setup and engine-bound routing/codec callbacks.  _(src: docs/notes/session12-eager-budget-recovery.md)_
- AV1 implicit bitrate efficiency remains 0.6 through ordinary cadence; above 30.5 fps it scales by sqrt(frameRate/30) capped at the H.264-equivalent budget. A global AV1 efficiency increase to 0.8 was rejected because it spent more bits and slowed the contested ordinary row.  _(src: docs/notes/session13-video-rate-alpha.md)_
- Compiling any WASM requires CSP script-src 'wasm-unsafe-eval'; WASM threads (SharedArrayBuffer) additionally require COOP/COEP, so the common path needs only 'wasm-unsafe-eval' and no isolation headers.  _(src: docs/architecture/08-packaging-and-loading.md)_
- Fixing the lazy-muxer race pushed the default/probe bundle above 256 kB, so default filter registration was changed to install cheap lazy FilterDriver proxies (webgpu-video-filter, canvas2d-video-filter, audio-dsp-filter, cpu-video-filter) that keep a synchronous supports() in the default bundle and import the concrete module only on first supported frame.  _(src: docs/notes/session9-lazy-muxer-filter-proxies.md)_
- H.264 two-pass pass one uses a fixed QP of 28 as a direct complexity proxy; a 0.6 complexity-blur curve allocates more bits to hard pictures without linear budget consumption; the H.264 six-QP-per-doubling model converts each picture budget to a QP clamped to [0,51] with bounded adjacent slew; pass two runs WebCodecs in quantizer mode. The retained schedule uses packed Float64Array timestamps + Uint8Array QPs = nine bytes per picture (O(1) presentation-order cursor, binary search for out-of-order lookups) — no per-frame Map/object graph.  _(src: docs/notes/session12-two-pass-h264-design.md)_
- Implicit offline video rate control was changed from 20 to 20 aggregate bits per output pixel per second scaled by codec efficiency and floored at 300kb/s; H.264 1280x720 gets 18.432Mb/s. The prior 9.216Mb/s H.264 720p budget scored SSIM 0.968371 (below 0.98 gate) on rotated 03.mp4; 18.432Mb/s scored 0.981680 (PASS).  _(src: docs/notes/h264-resize-quality.md)_
- Lazy audio containers keep synchronous mux contract via shared audio-container-mux-validation.ts because returning a proxy and loading the real muxer only on first async write would postpone invalid fragmented options and invalid/duplicate track errors; AIFF and CAF still reject createMuxer() immediately because their raw PCM output is served only through transformPcm. - ADR-024: FLAC decode is implemented in pure TS (not WASM) because FLAC is a lossless integer codec, making a pure-TS decoder bit-exact and Node-validatable without a browser or WASM toolchain (which this environment lacks); STREAMINFO's PCM MD5 is its own gold oracle, validated on the 8-file IETF FLAC conformance corpus.  _(src: docs/architecture/02-decision-records.md ADR-024)_

## Performance & measurement

- ADR-209 rotation/cohort-exact deficit gate separates two identities: correctness cells keyed by browser+scenario+baked/rotated filename slot+engine, and performance cohorts by browser+scenario+filename slot+source export (engines compared only inside one export). Only exports within 24 hours of the newest input satisfy current evidence; an absent/zero-sample/zero-median memory metric is explicitly unmeasured, not zero. The old generator keyed only browser+scenario+engine, letting reruns overwrite rotations and splice rivals from unrelated old exports.  _(src: docs/notes/session11-rotated-deficit-gate.md)_
- Session13 probe rows lose to mediabunny because the bounded metadata parser categorically excludes known-size video sources above 256 KiB, forcing a broader 32 KiB window read: probe/hevc_1080p_10s 4.305 vs 2.215 ms (1.944x), probe/h264_vfr 4.285 vs 2.070 ms; ADR-286's general smaller top-level walk lifting the payload-size gate is the fix.  _(src: docs/perf/session13-speed-ledger.md)_
- Direct ReadableStream input rejected fully buffering every stream before routing (violates bounded startup memory/time-to-first-work) and ReadableStream.tee() (two independently queued branches weaken backpressure and make cancel ownership ambiguous); decode() uses one memoized abort-aware materialization to an immutable byte source shared by audio/video/image because the container decode seam opens a source independently per track.  _(src: docs/notes/session12-readable-stream-input.md)_
- Encryption rows (cenc_ctr_decrypt) are structurally unwinnable vs ffmpeg.wasm: aibrush does decrypt + a FULL AVC decode-verify (verifyTrimmedAvcDecodeIfAvailable) while ffmpeg does decrypt-only, making aibrush ~2x slower (aibrush ~80-164ms vs ffmpeg ~33-67ms per file); the decode-verify is load-bearing (cenc-graceful-rotation.test.ts requires rejecting a structurally-valid IV mutation only full decode catches) and the workload is decode-bound so even a pipelined decrypt+decode leaves wall≈max(decrypt,decode)≈decode unchanged.  _(src: docs/perf/goal26-evidence.md)_
- The 2026-07-08 fair-harness upgrade rotates multiple real files per scenario with exhaustive scoring (metrics combine sum/max/median, a FAIL is never averaged into a PASS) and independently parses engine output so no engine grades itself — collapsing overfit passes and exposing large/long-file failures the single-fixture harness hid.  _(src: BUILD_INSTRUCTIONS_SESSION10.md)_
- The h264_resize_4k_to_1080p transcode is a genuine ~11x throughput loss (aibrush 4k decode→resize→encode ~4000ms best-case vs mediabunny ~1090ms; earlier measured 63282ms vs remotion 8417ms) because resize cannot passthrough; it needs a true WebGPU limited-range resize (deferred due to color risk) — canvas-pool was insufficient.  _(src: docs/perf/goal26-evidence.md)_
- The pure-TS bench --check regression gate uses a 0.5 tolerance (fails only on a >50% aggregate throughput slowdown) — loose enough to absorb machine-to-machine variance, tight enough to catch an algorithmic regression; throughput is reported in physically-meaningful units (×realtime for DSP, MB/s for byte ops, probes/sec for probe, never file-MB/s which would be dishonest for a bounded header read).  _(src: docs/architecture/14-benchmarks.md)_

## Public API & sources/sinks

- Trim on entropy-coded corrupt-source input is a documented honest limitation (ADR-043): an entropy-coded bitflip is undetectable at the container level without a full decode, so the engine keeps a graceful failure rather than faking a filename match.  _(src: BUILD_INSTRUCTIONS_SESSION3.md)_
- ADR-087: worker offload serializes the op (not the pipeline/closures) — ships the input ArrayBuffer transferred zero-copy plus mime/options minus sink; only encoded bytes stream back so no VideoFrame/AudioData ever crosses the thread boundary; a monotonic per-job 'epoch' stamp on every message prevents a reused bridge's in-transit chunk from cross-talking between jobs.  _(src: docs/architecture/02-decision-records.md ADR-087)_
- Packet provenance uses a module-private WeakMap keyed on the exact unlocked unpulled first-party ReadableStream plus an exhaustive semantic-equality proof of the TrackInfo descriptor; exposing a public brand or trusting a caller-supplied symbol was rejected as forgeable, and propagating provenance through a wrapper stream was rejected because a wrapper is a real cancellation/backpressure boundary the engine cannot prove without consuming it.  _(src: docs/notes/session13-native-track-clone-provenance.md)_
- The job-runner worker-boundary input is deliberately narrower than the flat host-facing MediaInput (excludes function-backed Source objects, URL instances, DOM elements, and live MediaStream handles) because those do not form one portable structured-clone contract.  _(src: docs/notes/session12-declarative-job-runner.md)_

## Other decisions

- The worker pool reuses one WorkerStreamBridge transport across jobs, so an in-transit chunk/done/error from a cancelled job N can arrive after job N+1's listener attaches; every message is stamped with a monotonic epoch (incremented per runStream) and stale-epoch messages are ignored (closing stale transferred frames) to prevent cross-talk between renditions.  _(src: docs/notes/worker-offload.md ADR-019)_
- ADR-076: pure-TS CPU filters (audio-dsp-filter, cpu-video-filter) declare FilterSubstrate:'native' (added), ranked webgpu→webgl→canvas2d→native→wasm; they had temporarily declared 'wasm' as the least-wrong value, which lied about what executed and blurred a real future WASM filter tail; force-software drops only webgpu/webgl.  _(src: docs/architecture/02-decision-records.md ADR-076)_
- Worker offload (ADR-087) serializes the OP not the pipeline: the host ships input bytes + flat options, the worker runs the same op on an inner engine forced worker:false and streams only encoded bytes back, so no VideoFrame/AudioData ever crosses the worker boundary for convert/trim.  _(src: docs/architecture/06-execution-and-runtime.md ADR-087)_
- Worker offload is opt-in: unset or worker:false means the inline path (the safe default) to avoid a surprise Worker spawn per heavy op; any spawn/handshake failure (e.g. Node, CSP-blocked module workers) downgrades to a byte-identical inline path.  _(src: docs/architecture/06-execution-and-runtime.md ADR-087)_
- A 31MB GPL FFmpeg/x264 single-thread WASM tail was rejected for the 2Mb/s quality gate because native x264 still misses the independent RGB gate at the exact rate and the WASM runtime violates the fastest/leanest objective.  _(src: docs/notes/h264-2mbps-quality-bound.md ADR-193)_
- Video pad canonical order is crop→resize→pad→rotate→flip→colour; untouched area is transparent RGBA zero (alpha-less codecs encode as black, VPx alpha targets retain transparency); pad never scales/crops; a no-op pad equal to current dimensions is omitted to avoid a pixel round trip; represented as a Blit shape. ADR-234 records the additive contract.  _(src: docs/notes/session12-video-pad-design.md)_
- ADR numbering high-water marks per session (never reuse): 042/045 (S2-3), 084+ (S4), ~102/103/105/108 (S5-6), 113/114/121 (S7-8), 118-120/122+ (S9), 181+ (S10), 187+ (S11), 213/225/226/228 (S12), 245+ (S13).  _(src: BUILD_INSTRUCTIONS_SESSION13.md)_
- Agent workflows must never run concurrently with a browser harness run — the browser starves and the run hangs (learned in Sessions 2/3); on a hang, pkill the run tree (run.sh/launch.mjs/serve.sh/'Chrome for Testing') and take the partial.  _(src: BUILD_INSTRUCTIONS_SESSION4.md)_
- Cross-workspace rsync of the vendored dist/ to ../media-test was blocked on 2026-07-12 by an exhausted escalation-credit window (retried at 04:47:59 and 04:48:13, still usage-limited) and only succeeded at 05:09 CEST; no alternate copy path was attempted because it would circumvent the workspace boundary.  _(src: docs/notes/session13-baseline-and-gate-repair.md)_
